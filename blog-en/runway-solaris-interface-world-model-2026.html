The screens in every app or website you use are pre-written by engineers into fixed code — press this button, that screen shows up, and the logic doesn't change. Runway's newly announced Solaris does something very different: the screen isn't written — it's generated, in real time, redrawn every time you interact with it.

Sounds abstract, so here's a plain-language walkthrough of what it actually does.

So what is Solaris, really?

Runway calls it an "Interface World Model." In short: instead of treating an app as a bunch of code running behind the scenes, it treats the entire interface as something being "drawn" like a video — every click and drag you make becomes a new frame, generated on the spot, rather than triggering some pre-written chunk of program logic.

Technically, it's built by adapting Runway's own Gen-4.5 video model: it's trained to take your clicks and drags as conditioning input, then generate frames one after another while staying as coherent as possible throughout the session (Runway says it can currently sustain full interactive sessions at 720p).

Official demo: the same starting frame (an X-ray of a hand) responds differently to the identical gesture. (Video source: Runway)

How is this different from how it's done today?

The usual pipeline is: a designer draws the interface, then an engineer "translates" it into code that actually runs. Details get lost in that translation, and every possible interaction has to be programmed in advance — if a user does something that wasn't coded for, the screen either does nothing or breaks.

Solaris skips the "translate into code" step entirely and generates the screen directly with a video model. Runway gives a pretty intuitive example: you can just say "move the table so I can see what's behind it," and it generates the result like a camera actually moved — instead of doing nothing because that specific interaction was never coded. Reflections shift with the lighting, and objects respond more naturally when manipulated, because that's exactly what video models are already good at generating.

Why can it respond to interactions it was never explicitly coded for?

Under the hood, it's a two-model split: a language model figures out what you're trying to do, and a video model renders the corresponding frames in real time. Once the language model interprets your intent, it hands off to the video model to generate the visual response — so an interaction the engineers never anticipated doesn't just freeze or error out.

Runway's own test results

Runway was also upfront about the limits of the current approach: they had several language models try to "recreate an interface from a single screenshot," and the pattern was consistent — the closer an image got to an actual photograph (versus something rule-based like a plain webpage or a slide), the more the reconstruction similarity dropped. That points to a real information-loss ceiling in the current "understand the screenshot, then generate code" pipeline.

They also ran a 250-person study, collecting 7,500 responses comparing interactions generated by Solaris against interactions generated by a language model (the comparison point was Claude Opus 5). On "which result better follows the instruction," 62% picked Solaris. On "which behaves more naturally within the scene," 72% picked Solaris.

What can't it do yet? (In Runway's own words)

  • Text rendering is still unstable: keeping text clear and undistorted during real-time generation remains unsolved.
  • It can be confidently wrong: since the screen is generated, it needs to be grounded in reliable reference material, or it can produce something that looks convincing but is actually incorrect.
  • Long sessions need work: coherence tends to drift the longer an interaction runs.
  • Accessibility isn't there yet: integration with screen readers and accessibility APIs is still pending.

When can you actually use it?

There's no public launch date yet. Runway's site has an early-access signup form open for anyone interested, including potential partners.

Bottom line

If this approach actually pans out, "software" might stop meaning "engineers build one fixed set of screens that everyone uses" and start meaning something generated on the spot, shaped by what you're actually doing in the moment — software starting to get "grown" the way AI video is, rather than "written." It's still early, and Runway is refreshingly upfront about the gaps, but it's a direction worth keeping an eye on.
